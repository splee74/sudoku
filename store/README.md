## 등록 순서

### 1단계 : 게임을 인터넷에 올리기 (GitHub Pages)

플레이스토어 앱은 인터넷에 올린 게임 주소를 앱으로 감싸는 방식(TWA)으로 만듭니다.

1. GitHub 저장소 `splee74/sudoku` → **Settings → Pages**
2. Source : **Deploy from a branch**, Branch : **main / (root)** → Save
3. 몇 분 뒤 `https://splee74.github.io/sudoku/` 에서 게임이 열리면 성공

> 폴더의 `.nojekyll` 파일은 지우지 마세요. 4단계의 `.well-known` 폴더가 인터넷에 올라가려면 필요합니다.

### 2단계 : 앱 파일 만들기 (PWABuilder)

1. <https://www.pwabuilder.com> 에 게임 주소 `https://splee74.github.io/sudoku/` 를 넣고 Start
2. **Package for stores → Android → Generate Package**
   - Package ID : `io.github.splee74.sudoku` 처럼 정하면 됩니다 (한 번 올리면 못 바꿈)
   - App name : 스도쿠 승급전 / Launcher name : 스도쿠 승급전
3. 받은 zip 안의 파일
   - `*.aab` : 플레이스토어에 올리는 앱 파일
   - `signing.keystore`, `signing-key-info.txt` : **앱 서명 열쇠. 잃어버리면 앱을 고쳐 올릴 수 없습니다.** 안전한 곳에 꼭 따로 보관하세요 (GitHub에는 올리지 마세요)
   - `assetlinks.json` : 4단계에 씁니다

### 3단계 : 주소창 없애기 (assetlinks.json)

이 파일이 제자리에 없으면 앱 맨 위에 인터넷 주소창이 보입니다.

**주의 :** 이 파일은 사이트의 **맨 앞 주소**에 있어야 합니다.
`https://splee74.github.io/.well-known/assetlinks.json` (O)
`https://splee74.github.io/sudoku/.well-known/assetlinks.json` (X, 안드로이드가 보지 않음)

그래서 GitHub에 **`splee74.github.io`** 라는 이름의 저장소를 하나 더 만들고, 그 안에 `.well-known/assetlinks.json` 과 빈 `.nojekyll` 파일만 넣어 Pages를 켜면 됩니다.
(나중에 자기 도메인을 사면 이 과정이 더 간단해집니다)

플레이스토어에 처음 올린 뒤 구글이 앱에 다시 서명한 "SHA-256 인증서 지문"도 `assetlinks.json` 의 `sha256_cert_fingerprints` 목록에 **함께** 넣어야 합니다.

> **주의 (2026-11 겪은 일) :** Play Console 화면에 보이는 지문(기존 키 · 양자 내성 키)을 넣어도 주소창이 계속 보였습니다.
> 실제 지문은 **App Bundle 탐색기 → 버전 → 다운로드 → "서명된 범용 APK"** 를 받아서
> `apksigner verify --print-certs 받은파일.apk` 로 꺼낸 값(`08:04:54:FA…`)이었습니다. 이 방법으로 확인하세요.

### 앱 파일 다시 만들기 (아이콘을 바꾸거나 새 버전을 올릴 때)

사이트(게임)를 고치는 것은 앱을 다시 올릴 필요가 없지만, **앱 아이콘 · 앱 이름 · 시작 주소**는 앱 파일 안에 들어 있어서 다시 만들어 올려야 바뀝니다.
앱 프로젝트는 `C:\dev\make_game\sudoku-android` 에 있습니다 (서명 키가 들어 있어서 GitHub에 올리지 않음. 따로 잘 보관).

1. `twa-manifest.json` 의 `appVersionCode` 를 1 올리고 `appVersionName` 도 바꿈
2. 그 폴더에서 PowerShell로 `bubblewrap update --skipVersionUpgrade` → `bubblewrap build --skipPwaValidation`
   (서명 키 비밀번호는 `signing-key-info.txt`. 아이콘은 사이트의 `icons/icon-512.png`, `icons/icon-maskable-512.png` 를 받아 씀)
3. 만들어진 `app-release-bundle.aab` 를 Play Console 에 새 버전으로 올림

### 4단계 : Play Console 에 올리기

1. <https://play.google.com/console> 개발자 계정 만들기 (한 번 25달러)
2. **앱 만들기** → 앱 이름 "스도쿠 승급전", 게임, 무료
3. 아래 "스토어 글", "앱 콘텐츠 답변" 대로 채우기
4. **개인 개발자 계정이면** 바로 공개할 수 없고, 먼저 **비공개 테스트**를 해야 합니다.
   테스터 **12명 이상**이 **14일 동안** 앱을 깔아 두어야 공개(프로덕션) 신청이 열립니다.
   가족·친구에게 부탁해 두면 좋습니다. (구글 정책은 바뀔 수 있으니 Play Console 안내를 확인하세요)

## 스토어 글

**앱 이름** (30자 이내)

```text
스도쿠 승급전
```

**간단한 설명** (80자 이내)

```text
하수에서 신까지! 4×4부터 9×9까지 한 단계씩 올라가는 스도쿠. 오늘의 퍼즐, 배지 모으기
```

**자세한 설명** (4000자 이내)

```text
하수에서 시작해 한 단계씩 올라가는 스도쿠, 스도쿠 승급전입니다.

■ 처음이어도 괜찮아요
작은 4×4 판에서 직접 눌러 보며 규칙을 익히는 따라 하기가 있어요. 계산은 전혀 필요 없고, 어느 칸에 어떤 숫자가 들어갈지 차근차근 따져 보는 놀이예요.

■ 10단계 승급전
하수 → 평민 → 중수 → 고수 → 영웅 → 지존 → 초인 → 패왕 → 대왕 → 신
하수부터 시작해 등급마다 승급 미션을 깨면 승급! 4×4, 6×6을 거쳐 9×9 판까지 점점 어려워져요.

■ 오늘의 퍼즐
매일 새로운 9×9 퍼즐이 하나씩 나와요. 같은 날에는 모두 같은 퍼즐이라 가족, 친구와 점수와 시간을 견주어 보세요. 하루도 빠지지 않고 풀면 연속 기록이 쌓여요.

■ 배지와 통계
첫걸음, 무결점, 5연승, 번개손, 일주일 개근… 46가지 배지를 브론즈부터 전설까지 모아 보세요. 성공률, 최다 연승, 평균 시간도 한눈에 볼 수 있어요.

■ 편하게 즐기는 기능
· 메모, 힌트, 되돌리기, 지우개
· 같은 숫자 · 같은 줄 강조 표시
· 다크 모드 (휴대폰 설정 따라가기)
· 파스텔, 나무판, 알록달록 등 10가지 판 꾸미기
· 큰 글씨와 큰 단추
· 처음 로그인한 뒤에는 인터넷 없이도 할 수 있어요
· 하던 판은 자동으로 저장돼요

■ 기록은 안전하게
Google로 로그인하고 닉네임을 정하면 시작할 수 있어요. 휴대폰을 바꾸거나 앱을 지웠다 깔아도 등급과 기록이 그대로 이어지고, 랭킹에 내 이름이 올라가요. 광고는 없어요.

■ 실패해도 괜찮아요
여러 번 틀려도 등급은 내려가지 않아요. 편하게 다시 도전하세요.

■ 숫자 도장의 전설
등급을 올릴 때마다 백운 사부와 함께하는 이야기가 한 장씩 열려요.
```

**카테고리** : 게임 → 퍼즐
**태그** (고를 수 있으면) : 스도쿠, 숫자 퍼즐, 두뇌 게임

## 로그인 설정 (Google)

로그인은 구글의 무료 서비스 **Firebase** 를 씁니다. 아래를 마치고 `js/config.js` 의 `FIREBASE` 칸을 채우면 로그인 단추가 켜집니다.
(채우기 전에는 "로그인은 준비 중이에요" 로 나오고, 게임은 그대로 잘 됩니다)

### 1. Firebase 프로젝트 만들기

1. <https://console.firebase.google.com> → **프로젝트 추가** → 이름 `sudoku-seunggeupjeon` 등 → Google 애널리틱스는 **사용 안 함** (개인정보처리방침과 맞추려고)
2. 프로젝트 화면의 **</> (웹)** 단추 → 앱 이름 "스도쿠 승급전" → 등록
3. 화면에 나오는 `firebaseConfig` 의 `apiKey`, `authDomain`, `projectId`, `appId` 네 개를 `js/config.js` 의 `FIREBASE` 에 옮겨 적기

### 2. 로그인 방법 켜기 (Authentication)

1. 왼쪽 **빌드 → Authentication → 시작하기**
2. **Sign-in method → Google → 사용 설정** → 지원 이메일 고르고 저장
3. **Settings → 승인된 도메인 → 도메인 추가** → `splee74.github.io`

### 3. 기록 저장소 만들기 (Firestore)

1. 왼쪽 **빌드 → Firestore Database → 데이터베이스 만들기** → 위치 `asia-northeast3 (서울)` → **프로덕션 모드**
2. **규칙** 탭에 저장소의 [`firestore.rules`](../firestore.rules) 내용을 그대로 붙여 넣고 **게시**
   - 내 기록(`users`)은 나만 읽고 쓸 수 있어요.
   - 랭킹(`players` 닉네임, `boards` 순위, `hall` 명예의 전당)은 누구나 볼 수 있고, 자기 줄만 쓸 수 있어요.
   - 말이 안 되는 기록은 규칙이 막아요 : 오늘의 퍼즐 1분 미만, 점수가 10초 안에 6만 점 넘게 오르는 것 등.
   - **규칙을 게시하기 전에는 랭킹 화면에 "랭킹은 준비 중이에요"가 나와요.**
3. 랭킹은 따로 색인(index)을 만들 필요가 없어요. (한 칸으로만 줄을 세우기 때문에 Firestore 가 저절로 만들어 둠)
4. 무료 요금제(Spark)로 충분해요. 랭킹 화면을 한 번 열면 읽기가 50~60번쯤 쓰이고, 하루 무료 읽기는 5만 번이에요.
   같은 랭킹은 1분 안에 다시 열면 새로 받지 않아요.

### 4. 카카오 로그인 (쓰지 않음)

카카오 로그인은 뺐습니다. Firebase 에 기본으로 없는 로그인이라 **Identity Platform 업그레이드(Blaze 요금제)** 가 필요하고,
업그레이드하면 OIDC 로그인은 한 달 50명이 넘을 때부터 1명당 요금이 붙기 때문입니다. (구글 로그인도 한 달 5만 명 제한이 생김)
나중에 다시 넣는다면 업그레이드 없이 무료로 되는 **서버 함수(Cloud Functions) + 맞춤 토큰** 방식을 권합니다.

### 4-b. 페이스북 로그인 (원하면)

지금은 꺼져 있습니다. 켜려면 `js/config.js` 의 `LOGIN_PROVIDERS` 에 `'facebook'` 을 넣고 아래 설정을 하세요.

1. <https://developers.facebook.com> → **앱 만들기** → "Facebook 로그인으로 사용자 인증" 고르기
2. 앱 설정의 **앱 ID**, **앱 시크릿 코드** 를 Firebase **Authentication → Sign-in method → Facebook** 에 넣고 사용 설정
3. Firebase 가 보여 주는 **OAuth 리디렉션 URI** 를 복사해서 Meta 앱의 **Facebook 로그인 → 설정 → 유효한 OAuth 리디렉션 URI** 에 붙여 넣기
4. Meta 앱의 **기본 설정** 에 개인정보처리방침 주소(`.../privacy.html`)와 데이터 삭제 안내 주소(같은 주소)를 넣고, 앱을 **라이브(공개)** 로 바꾸기
   (개발 모드에서는 Meta 앱에 등록한 테스터만 로그인할 수 있습니다)

### 5. 꼭 확인할 것 (휴대폰 앱에서의 로그인)

- 플레이스토어 앱(TWA)은 크롬으로 게임을 띄우는 방식이라, 로그인 창이 **크롬의 새 창**으로 열렸다가 돌아옵니다.
  인터넷 창에서는 잘 되지만 **앱으로 설치한 상태에서는 꼭 실제 휴대폰으로 시험해 보세요.**
  로그인 창이 떴다가 돌아오지 않는 문제가 생기면 알려 주세요. 다른 방식(같은 주소에서 로그인 처리)으로 바꿔야 할 수 있습니다.
- 앱 서명 열쇠의 SHA-1 지문은 Firebase 에 넣지 않아도 됩니다. (안드로이드 전용 로그인 방식이 아니라 웹 방식으로 로그인하기 때문)
- 로그인하지 않은 사람에게는 **승급할 때마다** (승급 축하 창을 닫은 뒤) 로그인을 권하는 창이 뜹니다. "다음에 할게요" 로 넘길 수 있습니다.
  `js/config.js` 의 `FIREBASE` 가 비어 있으면 이 창은 뜨지 않습니다.
